# PR #179: coverage follow-up to 087fd50

This report addresses the [audit of 087fd50](https://github.com/manifest-network/manifest-ledger/pull/179#issuecomment-5685889464). The audit confirmed all four preceding fixes and retracted its claim that the pagination-limit mutation had no failing test. This follow-up changes coverage tooling and test execution; billing/SKU behavior and the SDK pin are unchanged.

Confidence below concerns each reproduced finding, not the absence of all software defects.

| Finding | Severity / confidence | Verification and disposition |
| --- | --- | --- |
| Untested executable packages can be absent from binary coverage | Low / 100% | Reproduced with Go 1.26.8 and the Makefile's collection flags: raw `covdata` omits an untested leaf even though ordinary `-coverprofile` includes its zero-count blocks. Collection now captures both in the same Go invocation and merges them with the maintained `golang.org/x/tools/cover` parser. Independently, the diff gate parses every eligible changed source and rejects any logical executable statement without a corresponding profile block, including a missing function inside a partially present file. The real regression rejects the raw omission; after merging, evidence is complete but its 9/51 coverage still fails the unchanged 80% floor. The review's current `cmd/manifestd/main.go` example is not supported by the archived complete profile: both main blocks are present, with counts 1,500 and 112. The nine absent changed files in that profile are declarations/doc files. The future-leaf bypass remains confirmed. |
| One changed line receives a whole covered block's weight | Low / 100% | Reproduced using a real profile containing 172 covered statements and 42 newly uncovered statements. The old calculation passes at 172/214; the corrected gate counts only logical statements whose own token-bearing lines intersect the Git additions and fails at 1/43. Go's parser/scanner identifies statement ownership and excludes nested function bodies and comment-only changes from parent credit. Existing complete-profile source maps without missing statement locations and passes the stricter metric. |
| Repeating the command tests panics after SDK configuration is sealed | Informational / 100% | Reproduced `go test -count=2`. Root construction now runs in an isolated invocation of the same test binary, preserving subprocess coverage counters. Repeated, shuffled, and race-enabled package tests pass. Production initialization and SDK configuration are unchanged. |
| Cached vet output defeats the generated-API exclusion | Informational / 100% | Reproduced both cache orders: direct API analysis makes a later dependency-only visit replay unwanted diagnostics; the reverse order can conceal diagnostics on a later direct visit. The real repository reproduced 54 cached generated-code diagnostics. `make vet` now uses `-a`, preserving all analyzers and the API root exclusion while forcing fresh analysis. The full target passes; the deliberate cost is rebuilding dependencies, approximately 6–7 minutes in the local check. The pinned [Go vet implementation](https://github.com/golang/go/blob/go1.26.8/src/cmd/go/internal/work/exec.go#L1368) does not distinguish these visits in the cache action key. |
| Earlier local coverage runs can contribute stale counters | Additional low / 100% | Independently reproduced during verification: `covdata merge` adds timestamped counter files to an existing output directory. With the same binary, a second run that stops exercising a function still reports 100% through retained counters, versus 33.33% with fresh output. Coverage now cleans a dedicated `merged` directory at startup and uses only that directory for binary merge/text conversion. This was a repeat-run flaw; no contamination of a fresh hosted CI run was established. |

The full-diff metric is explicitly **logical executable statements selected by changed physical lines**. It differs from Go's block-level `NumStmt` and Codecov's line metrics. Multiple statements sharing a changed physical line count together. It does not claim branch or individual-expression coverage: case/communication headers have no independent statement counters, and Go does not instrument package variable initializers outside function bodies. Package-scope function literal bodies are included. Unsupported source-position directives fail explicitly. Declaration-only sources and empty bodies need no execution evidence; executable files receive no automatic platform/build-tag waiver.

Both Codecov 80% line floors and required contexts remain unchanged. The new tool uses the already selected `golang.org/x/tools` v0.48.0 through a direct module requirement and recorded checksums; it does not upgrade that version or change the SDK. The parser merges matching ranges and preserves hit/miss information without double-counting executions shared by ordinary and runtime reports. Invalid modes, paths, overlapping ranges, and inconsistent statement counts fail.

Validation passed: repeated/shuffled changed Go package suites, CLI race tests, all 21 Python checks (including real Go counter fixtures), root lint, complete `make vet`, workflow actionlint, and module tidy. The new Go tool's focused statement coverage is 95.4%. Full-PR gate results for the final commit are recorded in the PR response; combined historical-CI/local profiles are labeled as such and do not replace fresh CI on the pushed commit.
