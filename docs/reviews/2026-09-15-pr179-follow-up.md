# PR #179: September 15 follow-up

This report addresses the [review of 1c55952 and e25f49d](https://github.com/manifest-network/manifest-ledger/pull/179#issuecomment-5670766831). Confidence refers to each scoped finding and its verification, not a probability that the software has no vulnerabilities.

| Finding | Severity / confidence | Verification and disposition |
| --- | --- | --- |
| 1. Unsolicited denominations disable legacy complete-balance queries | Low / 99% | Confirmed through a real bank message and the SDK-configured REST gateway: adding 1,000 dust denominations to an account with one existing denomination changes an unpaginated request from success to HTTP 429 / ResourceExhausted. Explicit REST cursor traversal still returns every balance; original funds, lease reservations, and the withdrawal quote remain unchanged. The complete-or-error cap is retained. Operations/frontend guidance now documents persistent griefing, the absence of a general tenant-controlled sweep, and CLI/raw-REST fallbacks that do not require regenerating an old client. “Permanent” is too categorical: ordinary billing payouts can remove denominations used by leases, but there is no guaranteed cleanup and outsiders can send more dust. Filtering to tracked denominations would hide other usable deposits. |
| 2. Legacy unknown-field assertion was vacuous | Low / 100% | Confirmed: DiscardUnknown erased the evidence the assertion inspected. The test now retains unknown field 4, decodes its PageResponse, and requires it to be empty for a complete legacy response. The same decoder must detect the nonempty continuation from a real explicit page. An isolated mutation that suppresses that cursor fails the test. |
| 3. Billing and shared pagination maxima could drift | Informational / 100% | Confirmed duplicate sources of truth. Billing's maximum now derives from pagination.MaxPageLimit and the redundant second clamp is removed; the enforced value stays 1,000. The review's claim that no existing test detects a billing-only increase to 2,000 is refuted: the existing legacy boundary test fails under that exact isolated mutation. |
| 4. ACTIVE overflow takes auto-close before checked settlement | Informational / 99% | Confirmed. The comment now distinguishes the prior overflow guard from checked settlement for surviving ACTIVE leases. A regression creates and funds a tokenfactory-denominated lease through normal message handlers, acknowledges it, and advances time until accrued multiplication overflows. Direct checked settlement rejects; withdrawal instead auto-closes, finalizes the cursor, pays the target's collectible allocation, and preserves a sibling reservation. Bypassing the prior guard in an isolated mutation makes the regression fail. No settlement policy changed. |

The SDK pin and vesting implementation are unchanged by this follow-up. The current pagination limit and public wire/schema contracts are unchanged. Finding 1 remains an explicit protocol limitation with tested recovery of the balance view, not a claim that unsolicited deposits are prevented.

## CI and coverage

The previous Darwin build failed while downloading a Go checksum-database tile, before compilation. The exact endpoint subsequently returned HTTP 200 and the targeted retry passed without changing source, dependency pins, or checksum verification. The earlier GoReleaser transport retry also passed, including official SPDX semantics and the binary dependency inventory.

**Additional finding: incomplete patch comparison (Low, 99% confidence).** Codecov's patch comparison contained exactly the first 300 files from GitHub's compare response, excluding billing/SKU changes later in the full PR. This matches the documented [GitHub compare file limit](https://docs.github.com/en/rest/commits/commits#compare-two-commits). Its 78.12% patch result was therefore incomplete. The existing Go statement-weighted project check passed at 83.11%; Codecov's line metric is different and must not be substituted for that number.

CI now supplements the existing checks with a complete local Git comparison against the tested PR base/head. It weights each coverage block by its Go statement count when that block intersects an added line. Tests verify the greater-than-300-file case, literal filenames, binary Git attributes, malformed profiles, duplicate/overlapping blocks, thresholds, and empty eligible patches. The separate Codecov project/patch line floors remain 80% and both contexts remain required. Files absent from the supplied profile are reported explicitly; the profile-generation step retains responsibility for source completeness.

Added regressions cover actual signed testnet generation, preflight command failures, reservation rejection before transfers, caller-owned migration cache isolation, and import input ownership. Public preflight tests reject malformed billing/bank/auth inputs without mutating them and distinguish consumed current-state ACTIVE reservations from migration haircuts. Vulnerability-policy tests cover executable scanner/converter boundaries, exact profile forwarding, malformed reports, and output failures. Actual documentation generation and current/stale/missing-file checks run in isolated processes, preserving the SDK's global configuration and collecting their real coverage counters.

Combining the complete `e25f49d` CI profile with the added local profiles yields conservative line estimates of **81.69% project (11,603/14,204)** and **80.48% full PR (5,422/6,737)**. Existing coverage blocks are mapped only through unchanged source spans; the removed redundant clamp is excluded. These are combined local estimates, not fresh Codecov check results. The exact pushed head's CI results remain authoritative. The prior head's missing `codecov/project` context had no exposed YAML/BOT error and its report was complete; the underlying notification cause was not established, so no required context or threshold was removed.
